## Cammello 0.12.12

The four keychain prompts at every start on macOS are gone. They came
from the window build itself: the BotPassword prefill (1), the OAuth
token and secret for the status line (2, 3), and the keyring backend
probe (4) - all before the user had done anything.

Every access now happens at its moment of use: the BotPassword field is
filled when that dialog opens; the OAuth status is checked when the
Settings window opens; signing in reads the tokens exactly as before.
So the keychain asks when you act, not when the app starts.

One subtlety this required: settings are saved on close, and the
password field is part of that. A field that was never loaded is empty -
saving it would have DELETED the stored secret. A loaded/edited field is
saved as before; an untouched one is skipped. test_keyring_01212.py
locks all of it in, including that case.

Independent of this: whether "always allow" survives the NEXT build of
the .app still depends on the code signature. Unsigned or ad-hoc-signed
bundles get a new identity with every build, and the keychain forgets
the permission. With this change the prompts move to sign-in and
settings; with a stable Developer-ID signature they disappear entirely.
