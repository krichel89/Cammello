## Cammello 0.12.15

Geodata: the camera position out of the EXIF and into both halves of a
Commons file.

### The chain
Adding a file reads its GPS block along with the capture date - one EXIF
read, nothing to click. The value lands in the per-file description as
`coordinates=48.137154, 11.576124` and is shown in a "Coordinates" field
you can edit or clear. At upload it becomes:

    {{Location dec|48.137154|11.576124}}          in the wikitext
    P1259 "coordinates of the point of view"      in the structured data

P1259 is the CAMERA position, which is exactly what EXIF records - not
P625, which would be the position of the thing pictured and cannot be
derived from EXIF.

### Decisions worth knowing
- **Per file, never in the base block.** Every picture has its own
  position; one position for a whole session would be wrong for all but
  one of them.
- **Switchable.** Publishing a position is a decision, so there is a
  switch in the upload settings. Turning it off stops the automatic read;
  fields already filled stay, and "from EXIF" keeps working.
- **Bad values never reach Commons.** The value is parsed before use;
  anything unparseable or out of range is skipped and logged rather than
  written as a broken template.
- **RAW.** Pillow generally cannot read EXIF from camera RAW files, so a
  RAW-only shot yields no position. JPEGs work; a RAW+JPEG pair gets the
  position from the JPEG.

### New in the API layer
Until now every structured-data claim was a Q-number. Coordinates are a
different Wikibase datatype, so `set_structured_data` now takes either a
QID string or a `('coord', lat, lon)` tuple and builds the
globe-coordinate value (Earth, precision 1e-6 deg) itself.
